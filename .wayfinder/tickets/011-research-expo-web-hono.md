## Question

How does `expo export -p web` (or equivalent) output map onto the current "Hono serves the built client via serve-static from one port" setup? Specifically: what does the web build output look like (entry files, asset paths, index.html shape) compared to Vite's `dist/`; does Hono's `serve-static` config need to change; and what does the *dev-time* workflow become (replacing `npm run dev`'s `concurrently -k -n server,client "npm:dev:server" "npm:dev:client"` — i.e. does `expo start --web` replace the Vite dev server, does it need a proxy to the Hono API on :3000, or can it run standalone)? Also cover how `app.json`'s web config (favicon, title, theme-color, "add to home screen" metadata) replaces the current Vite `index.html` head tags.

## Resolution

`expo export --platform web` (with `web.output: "single"`, the right mode since Daybook has no router) produces a `dist/` shaped just like Vite's — one `index.html`, hashed JS assets, a `public/` passthrough — and Hono's existing two-call `serveStatic` SPA-fallback pattern in `src/server/index.ts` needs **zero changes** to serve it, verified directly against `@hono/node-server`'s source. The real gap is dev-time: `expo start --web` runs on Metro (port 8081), and **Metro has no equivalent of Vite's `server.proxy`** (confirmed via an open, docs-labeled Expo issue, expo/expo#35454) — so reaching the Hono API in dev needs CORS (`hono/cors`) plus an absolute `EXPO_PUBLIC_API_URL`, not a same-origin path proxy; `vite.config.ts`'s proxy block should be deleted, not translated. On head-tag/PWA metadata: favicon is auto-generated from `app.json`'s `web.favicon`, but title, theme-color, and the PWA manifest are **not** auto-generated by Metro (only by the deprecated Webpack pipeline) — for a non-Router app like Daybook these stay hand-authored in `public/index.html` + `public/manifest.json`, essentially relocating today's `src/client/index.html` approach rather than being subsumed by `app.json`. Full findings, sources, and a practical field-by-field mapping table: [expo-web-hono-integration research](../research/expo-web-hono-integration.md).
